# REFIT-Data-Cleaning-and-Appliance-Disaggregation
Take Home assignment for FlockEnergy

## Overview

This project was developed for the Flock Energy Data Science take-home assignment. It uses the REFIT Electrical Load Measurements dataset to investigate household electricity consumption and estimate washing-machine power from whole-house electricity measurements.

The project covers three tasks:

1. **Data cleaning:** Inspect and clean raw House 1 readings, resample them to one-minute intervals, and identify data-quality problems.
2. **Exploratory data analysis (EDA):** Analyse washing-machine usage across households, detect operating cycles, and compare usage patterns.
3. **Appliance disaggregation:** Estimate washing-machine power from aggregate household power and compare the estimates against simple baselines.

The objective is to build a transparent, reproducible analysis rather than a production-ready energy-management system.

## Dataset

The project uses the REFIT Electrical Load Measurements dataset from the University of Strathclyde. REFIT contains aggregate household electricity readings and appliance-level measurements from UK homes.

- [Official REFIT dataset page](https://pureportal.strath.ac.uk/en/datasets/refit-electrical-load-measurements/)
- [Raw REFIT data](https://pureportal.strath.ac.uk/files/62090177/REFIT_RAW_081116.7z)
- [Official cleaned REFIT data](https://pureportal.strath.ac.uk/files/62090184/CLEAN_REFIT_081116.7z)
- [Official cleaned-data README](https://pureportal.strath.ac.uk/ws/portalfiles/portal/62090183/CLEAN_READ_ME_081116.txt)

The raw data is used for Task 1. The official cleaned data is used for Tasks 2 and 3.

**Dataset files are not included in this repository.** Download them from the official source and place the extracted CSV files in the local directories described below. Do not commit the raw or cleaned dataset files.

## How to run

Run commands from the repository root.

### Task 1 — Raw data cleaning

```powershell
python src/clean_house1.py
```

This inspects and cleans raw House 1 readings. It generates a cleaned one-minute dataset, a quality summary, an outage report, and figures under `reports/`.

### Task 2 — Washing-machine EDA

```powershell
python src/washer_Eda.py
```

The script selects eligible households using data-quality and cycle-count rules. To specify households manually:

```powershell
python src/washer_Eda.py --houses 1 2 5 6 7
```

The script generates availability and cycle summaries, threshold-sensitivity results, and EDA figures.

### Task 3 — Appliance disaggregation

Run after Task 2:

```powershell
python src/disaggregate.py
```

To specify households and skip the leave-one-house-out experiment:

```powershell
python src/disaggregate.py --houses 1 2 5 7 --no-loho
```

The disaggregation script uses the one-minute data cache generated by Task 2. It produces model metrics, cycle-level evaluation, feature-importance results, failure analysis, and plots.

**Note:** These commands assume the filenames match the current scripts. If you rename a script, update the commands and any imports that refer to it.

## Modelling approach

The current disaggregation model is a `HistGradientBoostingRegressor` from scikit-learn. It estimates washing-machine power using features derived from aggregate household power and time information.

The model is compared with:

- Always-off baseline
- Global-mean baseline
- Usage-profile baseline

The evaluation uses a chronological split within each household: the first 60% for training, approximately the next 20% for validation, and the final 20% for testing, with one-day buffers between the splits. The validation period is used for model selection; the test period is reserved for final evaluation.

A leave-one-household-out experiment additionally tests generalisation to a household excluded from model training.

## Evaluation

The project reports power-estimation error, total-energy error, on/off detection metrics, and cycle-level metrics. It also includes actual-versus-predicted traces and a failure case involving overlapping household loads.

Results are documented in `RESULTS.md`. Data cleaning decisions and limitations are documented in `DATA.md`.

## Limitations

- REFIT represents UK households, so results may not transfer directly to Indian homes.
- Aggregate power contains overlapping appliance signatures.
- Sensor faults, missing readings, and timing differences can affect evaluation.
- The model is evaluated on a limited set of eligible households and should not be treated as universally generalisable.
- One-minute data provides more temporal detail than 15- or 30-minute readings.

## Possible improvements

- Evaluate additional households and alternative time periods.
- Investigate false detections and missed washing-machine cycles.
- Compare further interpretable models and NILM baselines.
- Test robustness to missing data and co-occurring appliance loads.
- Assess performance using coarser sampling intervals.
